The floating selection pill now formats at Excalidraw's depth.

FigJam and stock tldraw show too little; Figma is too much for a pop-up pill. This track brought the pill's formatting depth up to exactly Excalidraw's own control surface — 48 of its own vendored SVG glyphs, a stock pattern fill and draw dash, a real Opacity slider, and a full z-order/align/distribute Arrange cluster — all reading and writing through tldraw's own StyleProps and editor APIs. No new value model, no Figma-depth scrub inputs (that is the parallel inspector-panel track's job).

"figjam and stock tldraw give too little, excalidraw is just right, figma is too much for the toolbar, we use the side inspector for that" — "use the excalidraw icons exactly for showing things like line styling, line thickness, etc, so we don't need to reinvent another visual icon grammar."

Vendored icons, not a reinvented grammar

src/appearance/excalidrawIcons/ ports 48 glyphs verbatim from excalidraw/excalidraw's own components/icons.tsx — fill, stroke width, stroke style, sloppiness, arrowheads (as flip-aware components), font size, text align, z-order, and align/distribute. Every var(--icon-fill-color) became currentColor, so a glyph inherits the pill's own ink in both themes instead of painting black-on-dark. AppearanceGlyph.tsx's EXCALIDRAW_GLYPHS / EXCALIDRAW_ARROWHEADS lookup (7 families, 6 arrowhead values) outranks FigJam's traced icon exactly for these value/family pairs; a value with no Excalidraw analogue (tldraw's semi/none fill, the async dash, inverted/square/pipe arrowheads) keeps its existing app-drawn glyph rather than an invented one.

Attribution: NOTICE.md names all three real upstreams — Excalidraw MIT Font Awesome Tabler Icons — corrected during Wave 1 verification after the task prompt's "Excalidraw alone is sufficient" turned out to be wrong (Excalidraw's own icon file credits all three).

Opacity and Arrange — new, and entirely stock Editor calls

Both new pill items are registered as opacity and arrange in contextualSurfaceRegistry.ts, so BlockContextMenu.tsx (the right-click menu) can consume them later at its own merge — that 760-line file itself was not touched in this track.

The placement engine moved to Floating UI — same policy, proven twice

The hand-rolled FigJam flip math in the old selectionMenuPlacement.ts is gone; the pill now positions through @floating-ui/core@^1.8.0 with three custom middleware carrying the FigJam-specific semantics stock middleware doesn't have (vertical flip-then-pin-then-below, viewport-margin clamping, and a floor above the bottom tool belt). A frozen, embedded copy of the OLD math is diffed against the new engine across 4,608 generated cases in floatingToolbarPlacement.test.ts — every one matches. The real-browser journey above re-proves the one semantic most likely to regress in a swap like this: a selection dragged to the top edge still flips the pill to data-side="below" rather than clamping onto the shape (screenshot 8).

This placement-engine swap is a genuine architecture fork with real alternatives — per docs/peps/README.md it is written up as a numbered PEP at merge time, once it actually lands on main, not before.

Deliberately excluded

Kept out on purpose, so this track does not duplicate the parallel inspector-panel or workbench efforts, or fork a stock tldraw primitive it doesn't own:

  • Numeric/scrub inputs of any kind (exact px stroke, exact radius, typed opacity) — inspector-panel scope, a parallel worktree
  • Property tree / per-shape schema browsing — same inspector-panel boundary
  • Excalidraw's Edges (sharp/round) for geo shapes — tldraw@5.3.2 geo has no roundness prop; honoring it would fork GeoShapeUtil
  • Excalidraw's 3-level sloppiness — tldraw has exactly one 'draw' mode, so this maps to one option, not three
  • Zigzag-fill Alt-click easter egg, freedraw pressure, custom FontPicker, hyperlink/crop/line-editor actions
  • The bottom tool belt and BlockContextMenu.tsx — both explicit out-of-scope exceptions, untouched
