open-pencil — copy its grammar

  • Twelve sections in one orchestrator (DesignPanel.vue) that shows sections by selected node type — the same shape as the model's applies()2.
  • Reusable primitives with clean props: PanelSection {label, open, defaultOpen, empty, actions}, PanelGrid {columns 1–3, distribution equal|wide-first}, PanelFieldGroup, and PropertyListRoot exposing isMixed for fills/strokes/effects lists.
  • NumberField with a sensitivity drag — Base UI's ScrubArea gives you the same with pointer lock.
  • Tokens in a Tailwind v4 @theme block plus tailwind-variants — literally your target styling layer, minus the Vue.
  • Alive today (last commit 2026-09-07), MIT, 8.2k stars.

Onlook — a different problem, and the panel is not public

  • It styles arbitrary DOM with the whole CSS surface (padding, margin, display, typography). tldraw has a closed prop set — none of its schema logic transfers.
  • The public repo's right panel holds only the chat tab; the styling UI is the top editor-bar (48 files). Git history finds no move to the side3. Your screenshot's Styles tab is the hosted product4.
  • Both of its hard inputs are hand-rolled: a 169-line range scrub and a 795-line colour picker — the opposite of what you want.
  • Useful later, for one thing: the contextual top bar. SystemSketch already has a Figma-toolbar spike; Onlook's editor-bar is the right donor when that returns.

Excalidraw's Stats panel scores nearly as high as open-pencil and is the one reference that shares tldraw's problem exactly — a React whiteboard, a closed prop set, mixed values across a selection, drag on the label17. Read both: open-pencil for how the panel is organised, Excalidraw for what a whiteboard field must mean.

Why the earlier “no Tailwind” ruling does not bind the lab

The design-system report ruled out Tailwind as a repo migration — rewriting an already token-driven codebase, rules it can never reach because tldraw renders that DOM, and preflight's leak bugs15. Re-read today, all three cited issues concern builds that include preflight.css; none applies when it is never imported10. The lab is greenfield, and the SystemSketch side is additive: theme + utilities layers and an @theme inline bridge, no rewrite of a single existing stylesheet. The --ss-* vocabulary (67 names) stays the semantic layer; Tailwind becomes the authoring layer for new chrome only. That is a scoped reversal, and it should get a PEP at merge time, not now.

One fact that makes the bridge safe: tldraw namespaces everything. tldraw.css at the pinned version declares 129 custom properties, all --tl-*; the only other names in the file are --gradient-angle, --horizontal, --note-attribution-scale, --radix-popover-content-available-height, --radix-select-content-available-height, --radix-select-trigger-width, --radix-toast-swipe-end-x, --radix-toast-swipe-move-x, --safari, --vertical12. shadcn's --background, --primary, --radius and Tailwind's --color-* cannot collide with it. Write the bridge as @theme inline so each utility carries var(--tl-color-panel) itself and resolves on the element inside .tl-container — declaring the alias on :root would be guaranteed-invalid there, the trap the token layer already documents16.

And Kibo UI beside it

`npx shadcn add https://www.kibo-ui.com/r/color-picker.json` installed one file and pulled radix-ui@1.6.7 and color@5.0.3 into a project whose components.json style is base-nova — Kibo's source imports `Slider` from radix-ui unconditionally. With the tsconfig deprecation silenced, tsc reports exactly one real error: Kibo's <Select onValueChange={setMode}> was written against Radix's (value: string) signature and Base UI's Select passes string | null. So a Base UI shadcn project and a Kibo item are not composable out of the box: both primitive libraries end up installed, and the item needs a patch to type-check.

4 · Architecture: what the lab is, and how it comes back

Three rules hold it together, each with a test behind it:

  • The record stays stock. The lab's package.json pins tldraw@5.3.2; a stock-boundary test asserts the only tldraw seams used are components.StylePanel, ShapeUtil.configure (display values, customGeoTypes) and themes. Everything else is a bug.
  • The model decides, the view draws. FieldSpec { applies, read, write } is the contract; a row with no field is not rendered, and a field on a bare canvas whose paint seam is not installed is withheld (paintReaches). The same predicate serves both routes, so the two apps can never grow two field lists.
  • One source, consumed by copy, with a drift alarm. shadcn's model is that you own the files, so SystemSketch installs the registry item and then owns its copy; a sync test hashes the copy against the registry so a silent fork fails npm run check — the same shape as stage_app.mjs stamping which release it staged.

Three styling layers, and which one “expose everything” means

“Expose all the stylings tldraw's canvas supports” is three different jobs, and conflating them is what makes a panel lie. Layer 1 is schema: 51 fields already, all portable. Layer 2 is the renderer: 73 display values, 42 reached, 31 not — the frame set needs FrameShapeUtil.configure({ showColors }), geo's label margins and patternFillFallbackColor are plain to add, and url, altText, crop, growY, isPen, scaleX/Y are ordinary props nobody wired14. Layer 3 is the theme, which is a document/app setting, not a shape's — it gets its own tab. The stock-compatibility button you asked for (export → bare tldraw → pixel diff, ranked) is the instrument that keeps layer 2 honest, and it is still unbuilt14.

8 · What needs you

Q1 · Where does the lab live?

Recommend a new repo, /home/bam/tldraw_styling_lab. Its manifest is the proof of “stock + one thing”, it keeps Tailwind out of SystemSketch until the bridge is measured, and it does not share a git index with thirteen peer sessions. The alternative is labs/ inside this repo with npm workspaces — cheaper to share node_modules, but it converts this repo into a workspace root and every peer inherits that change.

Default if you say nothing: new repo.

Q2 · How does the panel come back into SystemSketch?

Recommend the shadcn registry (copy-and-own, with a hash-sync test). The alternative is a git-URL npm dependency with peer deps — one source, no copy, but the panel's Tailwind classes then need SystemSketch's build to scan node_modules via @source, and shadcn's own idiom is copy.

Default: registry.

Q3 · Tailwind in SystemSketch at all?

Recommend yes, layers-only, additive, bridged onto --ss-*, decided by the probe's pixel number and recorded as a PEP that scopes the earlier ruling rather than reversing it. The alternative keeps SystemSketch Tailwind-free and has the lab compile the panel's CSS to a plain stylesheet — workable, but it forks the styling of the very component you want shared.

Default: yes, at M5, never before the pixel gate is green here too.

Q4 · Kibo UI?

Recommend treat it as a gallery until it ships a Base UI track. The probe settled the composability question: its colour picker installs via shadcn add, drags radix-ui into a Base UI project, and produces one real type error against Base UI's Select. Use the picker library underneath it directly.

Default: not a dependency.

Q5 · The worktree claude/tldraw-inspector-panel-cf524c?

Recommend keep it as the donor, do not merge it; delete it once M2 lands the ported model and tests in the lab. Its §2 fixes are done; its §3 (the button) becomes M4; its §6 hero/report/review items are moot.

Q6 · Scope of V1?

Recommend V1 = M1 + M2 (inspector on layer 1 + the paint rows the configured utils reach). Theme tab, the census to 73, and the button are M3/M4.
