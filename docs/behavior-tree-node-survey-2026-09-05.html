Node primitives: Groot2, MoveIt Pro, Intrinsic Flowstate & SystemSketch

Not the skills you author yourself — the built-in structural vocabulary each editor ships to click-and-insert: control nodes, decorators, and the leaf/subtree scaffolding around them. Built for the Behavior Tree rebuild's Process view, whose own directive says to copy Flowstate's grammar — this is the reference material for that call. SystemSketch's column is read live from src/behaviorTree/btcppXml.ts at main / da392448, 2026-09-05.

Two reports already cover adjacent ground and aren't superseded by this one: the MoveIt Studio Pro · BehaviorTree.CPP · Groot2 prior-art atlas (28 entries, Copy/Adapt/Defer decisions across the whole editor — palette, inspector, runtime, replay, testing, not just node types) and the behavior tree representations research gallery (AICA + MoveIt Studio Pro + Flowstate → the Tree/Process/Data-Contract lens grammar the current rebuild implements). Neither had an exhaustive Flowstate node catalog — Flowstate and Selector don't appear in the atlas at all, and Flowstate's own docs didn't exist to atlas from until today's firsthand screenshots of its actual “Add Process” menu. This report is narrower and more current: just the insertable node vocabulary, cross-checked against the Behaviors library as it stands after the 2026-09-05 rebuild (6e55e90), plus two things neither prior report had: Intrinsic's own open-source SDK (found during this research) and MoveIt Pro's Sept 2026 10.0.0 editor changes.

Groot2 — the official BehaviorTree.CPP editor

Groot2 is not a curated subset of a smaller vocabulary — its palette mirrors the live BT.CPP node registry, read at runtime from a TreeNodesModel your C++ program emits, and it is larger than what BT.CPP's own tutorial docs enumerate. Its own docs describe Fallback as “known as Selector or Priority in other frameworks” — language Flowstate's own UI echoes almost exactly with its “Selector” menu item. The frame below is a real decoded still from Groot2's own product-demo video (behaviortree.dev/assets/medias/groot2_editor…mp4, t=8s): built-in nodes render as plain black text with no icon; the project's own custom nodes (ApproachObject, CloseGripper, GoTo, OpenGripper) get a small pencil glyph and blue-purple text, interleaved alphabetically in the same category list rather than split into their own section.

MoveIt Pro — PickNik's Objective / Behavior Tree editor

PickNik states this outright, not something to infer: “MoveIt Pro is built on top of the standard BehaviorTree.CPP library, though we have our own tightly integrated Behavior Tree editor and debugging environment.” It layers its own 4-way, colour-coded taxonomy on top of BT.CPP's registry (diagrams below, pulled directly from PickNik's own docs), adds a handful of its own decorators (SuppressChildErrors, ForEach/ForEachUntilSuccess, the 9.3+ deadlock-safe RepeatUnlessFailure… family), and folds BT.CPP's Condition concept into a plain “Behavior” tag rather than exposing it as its own filterable type. Its Sept 2026 (10.0.0) release added Ctrl+G “Group Under Sequence” — wrap a multi-node selection in a new Sequence in one keystroke — and a live red outline that highlights the failed branch when a Run fails and you switch back to Edit.

Intrinsic Flowstate — the reference the Process view is meant to copy

Flowstate has been in a gated beta since May 2023 with no public docs site — docs.intrinsic.ai and developers.intrinsic.ai don't resolve. This section is built from firsthand screenshots of the “Add Process” menu, recreated below as a faithful HTML mockup (not an original screenshot — the source images have no exportable file), cross-checked against a genuine primary source found during research: Intrinsic publishes an Apache-2.0 open-source SDK on GitHub (intrinsic-ai/sdk) whose README states it exists to write code for Flowstate, and whose behavior_tree.proto is confirmed by an in-repo comment to be exactly what “the graphical Flowstate Process editor” edits. That gave real operational semantics for five of the menu's items — but not the exact UI-label-to-backend-type mapping, and not what “Transitions” contains beyond the two items now confirmed by screenshot.

Not in the top-level menu, but present in the backend schema: plain Sequence, plain Fallback (classic BT.CPP-style ordered-tries OR, distinct from Selector), and a Data node (create/update/delete a blackboard value). Their absence from the palette lines up with press coverage describing an “expert mode” for hand-editing beyond what the graphical palette exposes — the five-item Control-flow submenu reads as a simplified, renamed subset of a larger vocabulary, not the complete node set.

Execution model, confirmed from the SDK: proprietary protobuf tree + CEL expressions + a blackboard, evaluated by “the executive” — not BehaviorTree.CPP, and node states are custom (ACCEPTED, SELECTED, EVALUATING_CONDITION, READY, RUNNING, SUCCEEDED, FAILED, SUSPENDED, CANCELING, CANCELED) rather than BT.CPP's four-state model. Flowstate is the odd one out of the three references on this specific point — Groot2 and MoveIt Pro are both literally BT.CPP.

What this means for the rebuild

Gaps worth closing

  • No “wrap selection in a named group” convenience. Both reference tools converged on this independently — Flowstate's Group and MoveIt Pro's brand-new (Sept 2026) Ctrl+G “Group Under Sequence.” SystemSketch's Behaviors library inserts raw node types only; there's no one-click way to name and collapse a run of existing nodes into a Sequence. Directly relevant to the Process view, whose own directive names a “titled group frame” as the visual for a named Sequence.
  • AsyncSequence and AsyncFallback are missing. Both are current BT.CPP v4.8 registry members (confirmed live from behaviortree.dev's own docs, and AsyncFallback was directly observed in Groot2's own palette) with real reactive-parent semantics distinct from the existing Reactive* variants. SystemSketch's model instead carries the legacy v3 SequenceStar alias, suggesting the pinned reference version predates this split.
  • Retry has no built-in recovery slot. Flowstate's RetryNode takes an optional recovery subtree run before each re-try; SystemSketch's (and BT.CPP's) RetryUntilSuccessful is count-only. Composable today via a Fallback wrapping a recovery Sequence, but not a single node — worth a call on whether the Process view should offer the composed pattern as one insertable unit.
  • No disable-without-delete. MoveIt Pro's floating selection toolbar has a “Comment out” action (disables a node in place, distinct from Delete). No SystemSketch equivalent — this corroborates the prior-art atlas's own A11 (“Disable / skip without deletion”), already decided Copy/adapt there; nothing new to decide, just a second independent source agreeing.

Validated by comparison

  • Per-primitive icon differentiation is the majority pattern. Groot2 and MoveIt Pro both give every control/decorator kind its own glyph and colour family; Flowstate is the outlier, using one generic crossing-arrows icon for all five Control-flow items. SystemSketch already differentiates per node (btGlyphFor in behaviorTreeModel.ts) — no change indicated here.
  • Fail as a dedicated forced-failure leaf is already covered. Flowstate's Fail and SystemSketch's existing AlwaysFailure are the same primitive under different names — a naming/copy decision for the Process view, not a missing capability.
  • “Selector” as Flowstate's word for Fallback matches BT.CPP's own docs (“known as Selector or Priority in other frameworks”), which strengthens the case for using that word in the Process view specifically, while keeping Fallback as the underlying XML/Tree-view name — the naming split the rebuild directive already implies by having two views on one canonical document.

Open questions — needs more evidence

  • Flowstate's “Debugging” menu contents are still unexpanded in every screenshot seen. The backend Debug/Breakpoint concept is a strong candidate match (Zach's own guess going in), but nothing confirms the UI actually exposes it there rather than elsewhere.
  • The “Fallback” tooltip on a Branch-shaped canvas node is still unexplained — the SDK has three textually distinct dispatch node types (Branch, Selector, Fallback) and nothing in the public source describes a single node with a switchable mode.
  • Two step-by-step videos were mentioned as available for cross-reference but weren't located in a vault sweep (Sources/Voice Notes, Notion Import, Apple Notes, video files by name/date) — point me at them directly if you want their content folded in.
