SystemSketch tldraw 5.3.2 Investigation · 2026-08-31

Rounded corners can survive the paste.

The failure is a narrow adapter gap: Excalidraw puts roundness in the clipboard JSON, but tldraw’s rectangle/diamond conversion branch discards it and the stock rectangle path is sharp. Both extension seams needed for a local fix are already public.

YES

Extend the interop layer, not the canvas engine.

Register an Excalidraw-shaped custom geo path, then override only the excalidraw external-content handler. Delegate everything else to tldraw’s existing converter. This preserves native labels, resizing, bindings, styling, export, grouping, and selection.

The visible failure

One clipboard field separates the input from the current result. The proposed result uses the same Excalidraw radius formula.

Excalidraw input

roundness: { type: 3 }

Adaptive radius: 25% of the short side, capped at 32 px.

Current tldraw paste

geo: "rectangle"

The roundness property is never read; the built-in path has four square corners.

Proposed adapter

geo: "excalidraw-rounded-rect"

A custom geo path keeps tldraw behavior while restoring the missing geometry.

The happy path

One custom geometry definition, one handler override, one narrow transformation, and a fixture-based regression gate.

1

Register the shape

Configure GeoShapeUtil with excalidraw-rounded-rect. It inherits labels, resize, fill, dash, links, snapping, hit-testing, and SVG export.

2

Override only Excalidraw paste

In <Tldraw onMount>, replace the public excalidraw external-content handler. tldraw deliberately registers user handlers last.

3

Transform geo creation

Build a queue of Excalidraw geo elements. During the delegated converter call, change rounded rectangles to the custom geo and retain {type, value} in shape meta.

4

Lock the seam with fixtures

Paste sharp, adaptive, proportional, labelled, grouped, rotated, linked, and arrow-bound rectangles. Assert type/meta/geometry and exercise one real browser paste.

// Shape geometry: preserve Excalidraw's actual algorithm.
const RoundedGeo = GeoShapeUtil.configure({
  customGeoTypes: {
    'excalidraw-rounded-rect': {
      getPath(width, height, shape) {
        const roundness = shape.meta.excalidrawRoundness
        const side = Math.min(width, height)
        const radius = roundness.type === 3
          ? Math.min(side * 0.25, roundness.value ?? 32)
          : side * 0.25
        return buildExcalidrawRoundedRectPath(width, height, radius, shape.props.fill)
      },
      snapType: 'polygon',
      icon: 'geo-rectangle',
    },
  },
})

// Paste seam: keep upstream conversion for everything except roundness.
onMount={(editor) => {
  editor.registerExternalContentHandler('excalidraw', ({ content, point }) =>
    putExcalidrawContentWithRoundness(editor, content, point)
  )
}}
Why not “just add roundness to putExcalidrawContent”? The converter is only half the gap. The stock tldraw rectangle schema and path have nowhere to store or render a radius. The custom geo type supplies that missing target representation; the handler supplies the mapping.

Acceptance gate

Ship rectangle support first. Treat rounded diamonds as the next small adapter case, not as a reason to build a general shape system.
