Speed is how quickly you close a learning loop.

The bottleneck is not code generation or test count. It is the rate at which one coherent user behavior moves from hypothesis → real app → human acceptance. AI slop appears when implementation batches grow faster than that judgment loop can close.

One closed-loop feature at a time—not one “robust subsystem” at a time.

The diagnosis

Local rigor, global drift

The individual bricks were often tested. The wall kept changing shape. That is why “add more tests” did not solve the felt problem.

The loop that produced the restart

Large batch; validation arrives late.

  1. Expand the product conceptWhiteboard + blocks + pipeline + hosts + file formats.
  2. Generate many locally complete featuresEach request looks reasonable in isolation.
  3. Harden the whole systemHundreds of tests pin a moving design.
  4. Use it and find interaction seamsThe human feedback queue opens after the batch exists.
  5. Accumulate exceptions and regressionsTests protect yesterday's assumptions.
  6. Restart from a clean substrateCoherence is recovered by discarding integration debt.

The loop to run now

Small batch; validation is inside the slice.

  1. Name one real user taskNot a component, layer, or visual language.
  2. Write its proof before codeAutomation + the human use that would make it valuable.
  3. Build the thinnest vertical pathUse stock behavior everywhere else.
  4. Run one real-browser journeyExercise input, persistence, and the integration seam.
  5. Use it for a real sketchZach accepts, rejects, or names one friction point.
  6. Harden only what failedPublish, then start the next behavior.

How to use the NASA V

Run a micro‑V per behavior

The V is not “specify high-level, let AI fill the bottom.” Its leverage is the direct pairing between every definition on the left and its evidence on the right. UI discovery still needs the final human-use gate.

Recommended first slice

Sketch three BAM components, connect them, reload, and keep editing.

This tests the product's actual spine—blocks + linking + persistence—while stock tldraw carries every generic whiteboard behavior.

Explicitly not in this slice

  • Excalidraw chrome parity
  • Ports or expanded block internals
  • Markdown, code, or image cards
  • Obsidian / VS Code hosts
  • Branch or release-management UX
  • A generalized semantic schema

Operating guardrails

The rules that keep AI speed additive

WIP = 1 behavior

Agents may parallelize research, variants, and tests for the same slice. They do not begin adjacent product behaviors before acceptance.

Fixed appetite

Give the slice one day or another explicit budget. Scope is variable; the time and proof are fixed.

Independent oracle

Reference app for familiar gestures, browser behavior script for mechanics, real human task for usefulness. The evolving app never grades itself alone.

Diff must be reviewable

If the behavioral change cannot be explained and inspected in roughly 15 minutes, the batch is already too large.

Delete and defer

Every slice carries a visible non-goals list. A good adjacent idea is parked, not quietly absorbed.

Done includes use

Green tests mean verified. A real task completed without unacceptable friction means validated. Both are required.

Immediate sequencing call: keep stock tldraw chrome. Do not port the Excalidraw interface next. Close the block → link → reload → edit loop first; copy an Excalidraw behavior only when that real workflow exposes a specific friction.
