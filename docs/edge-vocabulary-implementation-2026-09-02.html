A cable can now be read one iteration late.

Mark a cable delayed and it draws dotted with a z⁻¹ pill riding it: centred by default, slid along the cable by its own handle, and naming the initial value in the port-default grammar (z⁻¹ = 1.0). Solid stays the plain data cable; dashed stays reserved for the async rail. A switch in the Dev Hub draws the run after the pill dashed instead, so you can judge the two line styles on a real board. Built on top of the Branch track, proven in a real browser, not merged.

1 · What shipped, in the app

2 · Dotted, or dash after the pill

Zach was not sure which reads better once a delayed cable merges with others. Both are one switch apart on the same board, so the question can be settled by drawing rather than arguing. The dots are 6px apart; the dashes 8px long. On a short cable the pill covers most of the run either way; the difference shows on a long back edge.

3 · The record and the seam

Three props on the connection: temporal: 'data' | 'delayed' is a tldraw StyleProp, so the inspector, the right-click menu and a batch selection share one write and one shared-or-mixed report, exactly as routing does; delayValue is the text after =; pillPosition is a fraction of the routed arc length. The shape util samples the routed path (exact for elbow and straight, 64 samples for a curve), places the pill by arc length, offers a pill handle that projects the pointer back onto the path, and paints either one dotted path or two copies of the same smooth path with complementary dash arrays normalised to pathLength. The switch is an atom read by every delayed cable and remembered under systemsketch.cable-presentation.v1.
