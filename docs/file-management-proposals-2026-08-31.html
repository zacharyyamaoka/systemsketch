Add a real File menu, not a file-management product

The smallest complete move is a named local .tldr working file inside the existing stock tldraw menu. Keep IndexedDB as crash recovery, use Chromium's native file picker for Open / Save / Save As, and postpone the online-style workspace browser.

Recommendation: Proposal 2 · Named local file

Why: Proposal 1 is quickest but only creates downloads. Proposal 2 delivers the desktop semantics Zach is reaching for while still using supported tldraw and browser seams. It needs no new server, database, file tree, account, or sidebar.

V1 deliberately stops at

  • one current document
  • New / Open / Save / Save As
  • filename + dirty state
  • portable SDK-native .tldr
  • safe Stable → Preview duplication

Three viable cuts

Use the controls to compare what changes in the actual canvas chrome. The recommendation is the middle option because it is the first one that makes “Save” mean save.

Proposal 2 · Named local file

The canvas has one real disk file. Open and Save As return a Chromium file handle; Save writes back to that handle. The existing persistence key remains the crash-recovery buffer.

Trade-off

One small host state seam

  • Persist the handle and recent name in IndexedDB.
  • Permission may need one user gesture after restart.
  • Check the last-read digest before overwriting a file changed elsewhere.

The recommended ownership boundary

It composes two existing persistence layers instead of asking either one to do the other's job.

tldraw editor

Owns the live store, shapes, assets, migrations, and the public .tldr codec.

⇄

IndexedDB recovery

The existing persistenceKey keeps every in-progress stroke safe and restores the open board.

⇄

Named disk file

User-authorized file handle. Explicit Save writes SDK-native .tldr; Open parses and migrates it.

Happy-path seams already present

Stock menu composition

Override only components.MainMenu; render a File submenu first and then DefaultMainMenuContent. Edit, View, Export, Preferences, Language, shortcuts, and responsive behavior stay upstream.

Stock action wiring

Add New / Open / Save / Save As through TLUiOverrides.actions, then render them with tldraw's menu action item. Shortcut gating and menu presentation stay upstream.

Stock document codec

serializeTldrawJson includes schema, records, and media. parseTldrawJsonFile validates and migrates against the live editor schema before loading.

Browser-native file access

The installed launcher already requires Chrome or Chromium. showOpenFilePicker and showSaveFilePicker provide real handles; those handles can be retained in IndexedDB.

Two format rules that avoid a trap

Use .tldr in SystemSketch V1

The pinned SDK's public codec calls its portable format .tldr. It is text JSON and carries the schema needed for custom Block migrations.

Do not imitate offline's .tldraw extension

The separate tldraw offline product uses its own native .tldraw archive, including app-specific capabilities such as embedded scripts. That product is a UX oracle, not a codec dependency for this browser app.

Thin implementation sequence

Install the File submenu without changing the rest of the menu

Add four actions and the stock-looking submenu. Keep the current persistenceKey untouched.

Close one round trip

Draw → Save As controller.tldr → New → Open → verify shapes, pages, bindings, custom records, media, and camera behavior.

Add file identity and dirty state

Track the active handle, filename, saved digest, and whether editor changes diverge from the last successful disk write. Show Untitled • / Page 1 or controller.tldr / Page 1.

Make restart recovery honest

Store the handle in IndexedDB. If write permission is not retained, restore the local working copy immediately and ask for one click to reconnect before writing.

Fence external edits and Preview

Before overwrite, compare the file's bytes with the last-read digest. A Preview duplicate never inherits Stable's file handle; it starts as an independent Untitled copy.
