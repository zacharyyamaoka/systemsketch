Comments are implemented. On-board annotation is not.

The existing feature is a local, dock-first review-thread system with optional Python locator metadata. The click target → place leader/landing → edit visible text interaction is the distinct engineering-drawing primitive usually called a leader note, multileader, or callout.

→

Recommended direction: keep comments as collapseable review threads, add canvas pins as their lightweight spatial handle, and introduce a separate annotation/callout object for durable visible explanations. Do not make long-lived board callouts be comment threads whose layout is accidental.

Three different things, shown on the same board

1 · Current: dock-only comment

The selected Block is the anchor, but the anchor is invisible. The panel carries both the conversation and its only discoverability cue.

2 · Review comment: pin + thread

A small, toggleable pin says “there is a conversation here.” It opens the familiar thread without turning the conversation itself into board furniture.

3 · Annotation: leader + content

A visible canvas object explains something. Its leader and landing are presentation geometry, while its target reference remains semantic.

WorkflowThe right dock can compose, reply, resolve/reopen, delete, reveal, autosave, and inspect read-only comments.
Source locatorpath[:line[-line]][#symbol] is thread metadata. The present UI only copies its display string; it cannot resolve, open, relocate, or flag staleness.
Export.systemsketch retains local threads; portable .tldr strips them. Current comments are review-local, not diagram content.

Why “comment” is the wrong one-word name

A comment is a conversation: author, replies, open/resolved state, notification potential, and eventual removal from portable export. A callout is a visual assertion: target, visible content, leader route, text position, selection and editing. They may link, but should not become one object.

Why the hidden mode still earns a place

Some feedback should stay local and disappear when a board is exported or a review is finished. The dock-first implementation supports that. The missing piece is controlled pin visibility, alongside a different primitive for explanations that deserve to stay visible.

Source references: promising seam, intentionally incomplete product

Today

Input accepts path.py:24-31#symbol; it stores path, line span, symbol, and a possible digest. The only UI action copies the string.

Keep

Source is metadata on the thread, not identity. The board anchor remains authoritative because code lines move independently of diagram layout.

Before source navigation

Use a workspace-aware resolver and an honest stale state. Path + range is a locator; digest/excerpt or analyzer-resolved symbol makes drift visible.

Suggested first slice

First: use tldraw’s existing comments as intended—C/comment mode, pins on shape/point/region anchors, click-to-open thread, global pin visibility toggle. Preserve the local panel as the list and source/reference home.

Second, separately: one Leader Note tool: click target (arrowhead), click landing/card location, type. Begin with one leader, no automatic collision routing, and optional “link discussion” / “source reference” actions.

Do not: render every review thread as permanent text, treat manual line numbers as durable code identity, or auto-change Python from a canvas comment.

Prior art worth borrowing, not copying

  • tldraw commenting: point, shape, region, and page anchors; pins that open threads; pin drag; precise versus shape-level anchors; global hide/show.
  • FigJam comments: canvas comments plus right sidebar, shape/location/region attachment, resolve, and hide-from-board control.
  • AutoCAD MLEADER: arrowhead click, landing click, then text; the target association moves with its object while text stays placed.
  • Onshape Leader Notes: target snap, text placement, a moveable leader node, extra leaders, and target highlighting.
  • Bluebeam Callout: independently moveable text box and leader terminus, multiple leaders, and listable markup data.
  • GitHub review comments cautions that line anchors can become outdated; VS Code’s CommentThread API combines a URI + range with both inline and panel representations.
