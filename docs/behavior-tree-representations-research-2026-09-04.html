Behavior trees are a control grammar, not a second dataflow language.

Three production tools make the design boundary unusually legible: AICA’s reactive application graph, MoveIt Studio Pro’s classic BehaviorTree.CPP editor, and Intrinsic Flowstate’s process-shaped view of an underlying behavior tree.

Provisional SystemSketch decision

One canonical behavior-tree definition should support three deliberately different projections: Tree View for exact tick/priority semantics, Process View for an intelligible top-to-bottom procedure, and a focused Data Contract View for values, events, effects, and scoped blackboard state. Never draw every data dependency across the whole tree by default.

AICA application graph

Reactive system / data plane

Components own their lifecycle, predicates, and signal interfaces. Continuous signal wires coexist with discrete event and lifecycle paths.

  • One big application schematic
  • Signals can visibly animate at runtime
  • Sequence and Condition are event-engine primitives

Take: explicit edge kinds are excellent; this is not itself a behavior tree.

MoveIt Studio Pro

Behavior-tree / control plane

Classic parent→ordered-child topology carries the execution meaning. Action and condition leaves show their typed input/output contracts.

  • Sequence, Fallback, Decorator, leaf nodes
  • Compact port labels + hidden overflow
  • Runtime spinner/status on the actively ticked node

Take: retain the tree as the unambiguous semantic view.

Intrinsic Flowstate

Process / control projection

Sequences are flattened into a readable procedure; parallelism becomes fork/join rails; nested groups and recovery remain visible without a giant fan-out.

  • Vertical procedural spine
  • Nested, collapsible process groups
  • Status colouring makes the live path scannable

Take: it changes visual syntax—not behavior-tree semantics.

The useful split

The canvas grammar

Default state and on-demand disclosure

Tree View — default

top → bottomstructural controlcompact portsRoot is above ordered children. The command Tree orientation may switch to left→right, but it changes no order or execution meaning.

Process View

vertical procedurefork / joinnested groupFlatten only the presentation: Sequence becomes a procedural spine; Parallel becomes an explicit fork/join; recovery is a local detour. A group can collapse to one meaningful step.

Data Contract View

left → right valuesscoped read / writetunnelsReveal direct local producer→consumer wires around a selected leaf or subtree. Cross-boundary values use tunnels; a focused blackboard key reveals its readers and writers within scope.

Runtime trace

tick pathRunning / Success / FailureactivityShow what happened this run or tick. It is evidence over the static definition, never another hand-maintained diagram.

Why a unified default fails

Keep the topologies honest

InformationMake it persistentReveal on focus / trace
BT controlParent/child order, Sequence/Fallback/Parallel/Decorator, subtree boundaryLive tick route, abort cause, status history
Local valuesLeaf input/output contract, named port mappingDirect data wire and type/value neighbourhood
Scoped stateOwnership, scope boundary, declared read/write contractFocused blackboard key’s readers, writers, and recent mutation

The key restraint: a blackboard is not a free licence to draw a global hairball. Treat a local, declared port mapping like a function argument; show that wire when it helps. Treat nonlocal shared state as scoped storage, shown through a targeted topology or runtime lens.

Prior art, used precisely

What each tool proves

AICA: component orchestration can be dataflow-first.

AICA documents Signals as continuous typed data between components/controllers, and Events as discrete state-changing actions managed by its event engine. Its large canvas earns its complexity because it is a reactive application graph. Borrow its explicit edge taxonomy and runtime activity, not a claim that this graph is a BT.

MoveIt Studio Pro: a production editor keeps control structure first.

MoveIt Pro is built on BehaviorTree.CPP: action and condition leaves compose under standard controls and decorators. The port text in its tree exposes blackboard mappings, which is crucial semantic information, but is not the same as a drawn producer→consumer data wire. Its current release also says the editor removed manual line-drawing and re-lays out the tree as behaviors are placed—useful independent evidence for structured, automatic layout.

Flowstate: a process reading can be more legible without abandoning BTs.

Intrinsic calls Flowstate a flowchart-inspired graphical representation of behavior trees. Its process grammar is especially good at making a sequential recipe, nested group, parallel fork/join, and recovery legible at a glance. That is a projection of the same coordination logic, not a replacement for Tree View.
