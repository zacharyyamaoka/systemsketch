The Loop region, with the item on an ordinary solid cable

Golden 10's grammar was settled across two days of babble. This is the vertical slice of it: a for becomes a frame-like region whose header is an operator, and the element it emits travels on a plain solid cable — because dotted already means one turn late.

What "B solid drop" actually required

B is a claim about one cable, but the cable had nothing to hang off: there was no Loop region. So the slice is the region, and B falls out of one decision inside it.

The grammar saidWhat the code does
The header is an operator The collection lands ON the header through a real Iterable inlet — the same move a Branch makes with its controlling value — and the header emits the element from a real outlet directly beneath it. Nothing passes through the region on its way to a Block.
A real port, not a derived one Both are ordinary entries in the connection layer's port table, welded by the same binding, the same rules and the same paint as a Block's. The drawing stays wirable.
The item cable is solid This is the whole of B, and it cost nothing. The item outlet is an output port, and an output welds an ordinary temporal: data connection, which paints solid. Dotted is temporal: delayed — one turn late — and the loop's back cable uses it. The element is this turn's value, so it must not share that line. No new cable kind was needed to say so.
Centred title An operator's name belongs over the middle of it. The layout keeps it clear of the iterable label on the left and the turn chip on the right.

The one seam that had drifted

Adding a third port host produced a cable tldraw silently refused to bind. The drag died with no error, no console entry and no failed assertion — the state machine simply fell back to idle.

// ConnectionShapeUtil.canBind, before
return bindingType === 'connection'
    && fromShapeType === CONNECTION_SHAPE_TYPE
    && (toShapeType === 'block' || toShapeType === 'branch')

isPortHostShape kept one list of hosts and canBind spelled out another by hand. They agreed for two hosts and disagreed for three. Both now read one exported PORT_HOST_SHAPE_TYPES, so a fourth host can only be forgotten in one place.

Two things the first screenshot decided

Neither was visible in a unit test, and both were obvious the moment the acceptance journey painted a real board.

  • The item label moved below its dot. It sat beside the dot, on exactly the row a cable leaves along — so the first cable drawn from that port struck the word through.
  • The item port moved onto the wall. It was inset on the header's top edge; it now sits at the header's bottom corner directly under Iterable, which is where Zach drew it.

Known, and deliberately left

The item cable's elbow route laps the region. The binding is right and the line style is right; only the path is ugly. The live paint asks every port to leave rightward and escape its shape's box, and a region's box is the whole region. Fixing it means changing box construction shared with every Block cable, which belongs in its own slice behind the routing corpus rather than bolted onto this one. A card on the review board says so.

Not built, and not pretended: the faded zero-iterations arm (it needs the analyzer's last/zero φ, not just a shape); a live iteration counter (turn is a plain string prop today, so the chip renders whatever it is given); authoring the port names from the inspector; break, else, and nested loops.
