Four-sided port labels: use an inward, horizontal rail

A four-sided node editor does not need four writing directions. The durable convention is to keep a port’s source-shaped label horizontal and put it just inside the face: below a top socket, above a bottom socket. That makes the socket-to-label relationship local while preserving the outer side for wires.

Recommendation for SystemSketchTop and bottom labels remain horizontal monospace text, centred on their socket’s x-coordinate. A top label’s first baseline is below the dot; a bottom label’s last baseline is above it. Keep the face’s port order left-to-right on both rails. Do not rotate labels, place them outside the Block, or let them overlap one another.

One familiar reading rule

Every label moves toward the Block’s centre: right of left-side ports, left of right-side ports, below top ports, above bottom ports.

Why not orient text with the edge?

Rotation makes code-like names vertically scanned and puts the word in the exact external corridor a perpendicular wire uses.

Exact layout contract

1

One baseline direction. Keep name: Type horizontal at every side. SystemSketch’s typography rule treats port text as source-shaped material; rotating it changes how the reader has to decode the same identifier.

2

Inward, never outward. Top: dot → 6px gap → label below. Bottom: label above → 6px gap → dot. This is the top/bottom equivalent of today’s inside left/right labels, and it keeps the cable’s departure zone clean.

3

Centre label and dot on the same x-axis. The label is a compact single line such as item: Iter, using the normal port grammar—not a rotated side caption. On both horizontal faces, authored port order reads left-to-right.

4

Reserve a rail; do not solve density by distortion. Top/bottom names need a dedicated inside band so they cannot collide with a title, footer, or child canvas. If a Block becomes too narrow for its authored labels plus a 12px gap, retain the sockets and use the existing compact/overflow affordance; do not shrink, stagger, rotate, or allow name overlap. This preserves the whiteboard’s authored order without turning one face into an unreadable many-port table.

How it fits the current canvas

The existing Loop is the useful local proof: its bottom-edge item port places its label above the dot specifically to prevent a downward wire crossing the words. The current generic Block similarly puts an effect port on its top edge, but intentionally gives it no label. This proposal is only a presentation rule for future named top/bottom ports; it does not derive sides, rename ports, or change wiring semantics.
