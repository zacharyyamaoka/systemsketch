1 · What landed

The model. Three optional fields on a port, so every older board still loads unchanged: mutates on an input (the call writes this argument in place), effect on an output (this value leaves by the top edge), and edgeT (where along that edge it sits). The port is derived: reconcileEffectPorts creates one for every marked argument and removes it when the mark goes, and it runs inside patchBlockPortProps so the inspector, the context menu and a tool draft all get it from one place.

/**
 * Where an effect port belongs, given the cable someone actually drew.
 *
 * The port has no slot: its existence comes from the signature and its position
 * from the route. `boundaryCrossing` answers the geometry for any container, so
 * this is only the policy — take the first place the cable leaves the block, and
 * use it when that place is the top edge. A cable routed out of another edge is
 * not an error (the whiteboard may do as it likes), it simply does not move the
 * port, and `effectExitLint` is what reports it.
 */
export function effectPortEdgeTFromRoute(
	points: readonly ElbowPoint[],
	box: ElbowRect,
): number | null {
	const exit = firstExit(points, box)
	if (!exit || exit.side !== 'top' || box.w <= 0) return null
	return clampEdgeT(exit.point.x / box.w)
}

The layout. An effect output is pulled out of the right-hand lane before the body is planned — it must not take a row slot, or the rows would space around a port that is not there — and placed along the top edge afterwards. The placement goes through edgePortPoint, which is deliberately generic: a group boundary port, a region tunnel entry and a collapsed-group badge all need the same thing, and this is the seam they should share rather than each inventing one.

The cable. Nothing is persisted. A connection asks the port it leaves whether it is an effect port, and draws itself accordingly — warm, a shade heavier than a data cable, with a mut pill, and never in the near-black that control cables own. That keeps one fact in one place: mark the argument and every cable off it changes with it.

The geometry module is the one Zach asked to be general purpose. It knows nothing about mutations: boundaryCrossings, firstExit, lastEntry, firstExitPerBox, prefersSide take a rectangle and a polyline and answer where they meet, which is what lets a derived port be placed by the cable instead of by a slot.

4 · Decision surface

Done and proved

  • Mark an argument → the hook and the effect port appear; unmark → both go. Driven in the browser, both ways, and across a reload.
  • Cables off the port draw as effect cables with the mut pill.
  • 33 unit cases; the whole suite green.

Left

  • Next: nothing calls effectPortEdgeTFromRoute yet — the port does not follow a dragged cable in the app, though the function and its tests are there. That wiring is a side effect on the connection's route, and it is the obvious next commit.
  • Next: effectExitLint is written and tested but not surfaced anywhere in the UI.
  • Not started: the analyzer emitting effect ports from real Python; the auto-fade of displaced cables.

Needs you

  • The ink. Warm orange at 2.6px is what shipped; say the word if you want it nearer black.
  • Where the toggle lives. It is an inspector chip today; the port's right-click menu is the other natural home.

Deliberately not done

  • No new connection prop — the look is derived, so it cannot drift from the block.
  • No migration: the three port fields are optional, so every older board loads untouched.
  • No change to how named outputs lay out.
