Ports in the header, and the rows they live in

A Block still has only input and output ports. What changed is that every port now says which row of the burger it sits in — the heading is row 0 — and you can put a port in any row from four places that all agree: a hold-and-drag on the canvas, a grip drag in the inspector, a Move to menu, and a bead on the heading's edge that adds a port straight into it.

What changed in the thinking

  • Affirmed: the header is a row. Your instinct that "a header port is just an input port; the header row is special only in that it takes no outputs" is now literally the model: row: 0. Nothing else distinguishes it; the layout paints row 0 in the heading band because that is where the control-flow data belongs (callable, predicate, iterable — your Aug 27 rule).
  • Rows moved off the dividers and onto the ports. Until today a row was a marker on the port that started it (groupStart), an arm likewise (branchStart), the heading a flag. That encoding could not say "row 3 on the inputs, nothing in row 2" — which your inspector mock draws — and dragging a row's first port out carried the line with it. Now row and branch are on each port, a migration replays the old split rule, and rows are shared by both lanes by construction.
  • One honest limit, chosen on purpose. A row exists because a port claims it, so moving the last port out of a row compacts the row away. Your rule that rows "should be driven from another place" points at the next step, not this one: when rows get labels (your Conditional sketch's if: / elif: bands) or come from code, rows become Block-level state and ports reference them. Everything built today survives that move unchanged.
  • "Match the inspector to the window" is one rule, not one gesture. Both surfaces show the same grammar — a card in flight, a tinted band for the row you would join, a rule where you would land, nothing moves until you release — and both land through the same reducer. The gesture differs because it must: a press on a canvas dot is a cable, so the canvas needs the hold; a list grip means drag, so it drags at once.
  • One level deeper, not built: your Conditional sketch gives every row its own label band (if:, if else:, else:). Read that way the heading is not special at all — it is row 0's band, and a row's band is where if cond:'s cond would sit. Worth keeping in view when rows get labels.

blockPortSections(props) is the one table — header, then rows with their inputs and output arms — that the layout, the inspector, the drop rule and the row menu all read. normalizeBlockPortRows keeps rows dense from 1, arms dense from 0, header ports inputs-only, and each lane's stored order equal to its visual order. The layout now also emits headerBand and sections[] bands, so a pointer's y alone names a row, an arm, or the heading — in Port and Expanded view alike.

moveBlockPortToSection(side, portId, { row, branch, before }) is the single assignment reducer. The place is expressed against a neighbour id, never an index, so hidden ports keep their position; a drop that changes nothing returns the same object and opens no undo step.

Decision surface

Done and proved

  • Ports carry row/branch; markers migrated; files from before open unchanged.
  • Heading bead adds a header port; hold-and-drag lands in the heading, any row, any arm, in Port and Expanded.
  • Inspector lists HEADER / ROW / BRANCH lines in canvas order; grip drag across a line; arrows step visually.
  • Right-click Move to: Header, Row n, New row below, New branch below.
  • All of it in the product composition; every neighbouring journey green.

Left, and merely next

  • Rows as Block-level state with labels (if:/elif: bands) — needed before an empty row can exist or a row can be reordered from "another place".
  • A long-press on the inspector row's margin (not only the grip), as pyblocks had.
  • Keyboard shortcuts for the port menu commands — still waiting on the port selection model.

Needs you

  • Which surface to lean on. Recommendation: V1 drag as the primary, V2/V3/V4 kept as complements (all shipped). default if silent: keep all four, polish V1
  • Empty rows. Today a row emptied on both sides disappears. Recommendation: accept until rows get labels. default: accept
  • Migration ids: resolved, no action. The pill branch has since merged this work and renumbered its own ValueView to 4, keeping PortRows: 3. Verified against that branch when this report was built. nothing to decide

Deliberately not done

  • No V5 port-editing mode in the app — a mode is the one thing every earlier round of yours rejected.
  • No pyblocks writer rule for rows; the record is ready for it (row/branch per port).
  • No per-row label bands.
