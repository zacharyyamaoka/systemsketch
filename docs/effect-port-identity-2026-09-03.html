Telling mutated ports apart

Zach, after the effect-ports implementation shipped: "What happens if you have like multiple ports that are being mutated. how can you tell them apart? ... now it's time to harden and stress test this." This is that hardening pass — an enumeration, ten drawn variants, an effect-kind table, and nine hostile boards. Nothing here is a decision; every variant carries what it claims and what it costs, and every stress case says plainly which variants it kills.

0 · The gap, verified before anything is drawn

Two arguments marked mutates, in the order a person would actually click them. reconcileEffectPorts (src/blocks/blockModel.ts) gives every newly-added effect port edgeT: EFFECT_EDGE_T_DEFAULT — 0.5, unconditionally. Nothing in the reconcile spreads a second or third one apart. Mark primary, then backup, and both land on the identical point on the top edge until a person drags one away by hand. Every other board on this page assumes that dragging has already happened; this is what it looks like before it does.

One correction made on this page. docs/effect_board_svg.py's EFFECT constant is bound to THICK (near-black, #15181f) — a holdover from before the ink was settled. The shipped cable (src/blocks/connections/effectCable.ts) paints var(--ss-warning), a warm orange, at 2.6px — which is also what effect-ports-3-wired-2026-09-03.png shows. Every effect cable on this page is drawn in that warm ink explicitly; effect_board_svg.py itself was left untouched, since three other builders import it mid-flight.

1 · Ten variants

Every panel draws the same block — reconcile(primary, backup, preview), three mutated arguments, two of them an unrecognised type (Cache, so portColor falls back to the one grey-gold any bucket) and one recognised (Image, violet) — so the ten are directly comparable.

V1 — Label the port shortlisted for Part 3

Claims: Paint the argument's name directly beside the port dot on the top edge.

Because: The name is always right there, with zero inference.

Costs: Ink on every mutated block whether or not it is ambiguous, and text needs lateral room the top edge does not reliably have (stress 3, 4, 9).

V2 — Name the pill shortlisted for Part 3

Claims: Keep the port bare; the existing `mut` pill on the cable carries the argument's name (`mut poses`) instead of the generic word.

Because: Nothing new on the block itself — only a cable, once drawn, gets the label.

Costs: Invisible on an unwired mutated block, and a long name widens the pill until it collides with a neighbour (stress 3).

V3 — Inherit type colour shortlisted for Part 3

Claims: The port and hook inherit `portColor(type)` — the colour a data port already carries.

Because: Reuses a channel readers already decode; zero new ink, zero new legend.

Costs: Two same-type mutated arguments are the exact case that needs telling apart, and most domain classes (`Cache`, `Pose`, `Task`) all fall into the one grey `any` bucket anyway — colour distinguishes types, not identities.

V4 — Positional invariant

Claims: No mark at all: the Nth mutated argument in the signature is always the Nth effect port from the left.

Because: Costs zero ink and becomes muscle memory — read left to right, done.

Costs: Directly contradicts the settled rule that a port's position comes from where its cable crosses the boundary, not a slot (`effectPortEdgeTFromRoute`); the first drag breaks the invariant with nothing on the board to say so.

V5 — Interior tether

Claims: A faint dashed line runs inside the block from each hook up to its port.

Because: The correspondence is drawn once, geometrically — no names to read at all.

Costs: Interior wiring is a new convention nothing else in the idiom uses, and three tethers from three rows converging on three nearby top points reads as a tangle, not a diagram.

V6 — Paired ordinals shortlisted for Part 3

Claims: Number the mutated hooks in signature order; the same numeral repeats on the port and its pill (`mut ①`).

Because: The shortest possible label that still scales to any number of mutations.

Costs: The numeral is arbitrary — you still look at the hook to learn what ① means — and it is the same device Zach rejected for cable identity on golden 06 (`pose#1`/`pose#2`), though that ruling was about version provenance, not simultaneous arguments; worth his eye either way.

V7 — Bundled effect port

Claims: Collapse every mutation into one effect port; its cable fans out and only the landing — back at each hook — carries a name.

Because: The top edge never grows past one mark, no matter how many arguments are mutated.

Costs: A cable that leaves the top and immediately re-enters the same block reads as a loop or a bug before it reads as three effects, and the single trunk hides count at a glance.

V8 — Hover / selection coupling shortlisted for Part 3

Claims: At rest every port is an identical bare dot; selecting or hovering one lights up its argument's row elsewhere on the block.

Because: Zero resting-state ink — scales to any N for free, and matches how tldraw already surfaces hover affordances elsewhere.

Costs: Provides nothing to a screenshot, a zoomed-out board, or a first glance — it only exists while a pointer is on it.

V9 — Labelled effect band

Claims: Give effects their own reserved band along the top, one row per effect, the way the header band already reserves row 0 for the receiver.

Because: Effects become a first-class row structure instead of points scattered on a line, so they stack instead of colliding.

Costs: A real structural addition, not a paint job — it competes with the title for vertical space, and it re-introduces a slot exactly where the shipped design deliberately has none (position derived from the cable, not a row).

V10 — Signature notation (&mut)

Claims: Borrow the signature notation of a systems language — `&mut poses` — and put the mark in the block's title text instead of beside any port.

Because: Reuses reading skill a systems-literate audience already has, and the mark is text, so it is copyable and greppable.

Costs: Opaque to anyone who has not written Rust, and the title is already the most crowded line on a narrow or collapsed block.

2 · The effect-kind table

Whether the shipped mutated-argument port design serves, extends, or breaks for every effect kind worth naming.

Mutates an argument`copy_into(dst, src)`, `poses.append(pose)`servedShipped. `reconcileEffectPorts` derives the port; this whole page is about the one gap in it — telling several of them apart.
Mutates the receiver (`self._task = …`)an instance method, golden 36's shapeextends`portInHeader` reads `row === 0` on an ordinary input — a header/receiver port is already just a row-0 member of `props.inputs`. `reconcileEffectPorts` filters `props.inputs.filter(portMutates)` with no header check at all, so a receiver flagged `mutates` already derives an effect port for free at the model layer. Unverified: whether the inspector's checkbox is currently exposed for a header-row port, or only for body rows.

The whole derivation (`effectPortId(inputId)`, `mutatedInputId`) is keyed off an input id that does not exist here. Needs an anchor the model does not have: some notion of a project-level symbol a block can point at.
I/O out (`print`, a file, a socket, a device)`print(status)`, `log.write(line)`breaksNothing in scope changes name or value — there is no argument whose next read should rebind to a new version, which is the mechanism this whole feature rests on. Raises / control-flow escape`raise ValueError(...)`, an early `return` past cleanupbreaksNot a value flowing anywhere — an exit that skips the normal one-output-continues-right shape entirely. Needs an escape-edge concept with no relationship to a port.
Acquires / releases a resource (`with open(...) as f`)a context manager bracketing a sub-region of the bodybreaks (as a port) / maybe-extends (as a region)Two effects — enter and exit — bracket a whole scope, which is a region concept (closer to Branch/Loop) rather than a single call's port. Forcing it onto a port per mutated argument would need one 'argument' for the resource and would still say nothing about the span it covers.
Async scheduling (`asyncio.create_task(...)`)fire-and-forget, runs laterbreaksA temporal fact, not an in-place write — the delayed-cable / `z⁻¹` vocabulary already exists for 'this arrives later' and is the more natural home for it. The mut-port grammar has nothing to say about deferred execution at all.
Logging / telemetry (high-frequency)a `logger.debug(...)` on every iteration of a loopopen question — argued in the promptNot a modelling gap so much as a volume one: nothing stops a port+cable per log call, but a board with one on every line stops being a board. The live question is whether this should be drawn as a port at all, or suppressed to something far smaller (a tiny corner tick, never a full effect port) — or simply not drawn. No verdict taken here on purpose.

2b · Hidden state gets its own section

The shipped rule is "top edge = what this block does to something it did not create." But random(), time.now(), os.environ and a file read all bring something IN that the block did not create — an effect flowing inward, which the rule as stated has no words for. Three candidate answers, no winner taken.

(a) Top edge, bidirectional. An effect port becomes a source as well as a sink; direction is carried only by the arrowhead.

  • Reuses one edge and one vocabulary — no new grammar to learn.
  • An inward and outward mark share a lane, so a block that both reads hidden state and mutates an argument needs the two told apart at a glance, by arrowhead alone.
  • Directly reopens the settled "top = out" reading — everywhere else on this page depends on that being one-directional.

(b) A different edge. Left, since a hidden read is still technically a value coming in — but a second, unnamed lane no declared argument uses.

  • Keeps the top edge meaning only one thing, undisturbed.
  • "Left" already means "declared argument"; a second lane on the same edge is a new sub-convention, not a reuse of an existing one.
  • Nothing to bind a cable to — there is no upstream producer to route from, so the mark can never look like an ordinary port no matter which edge it sits on.

(c) A different mark, not a port. A static corner glyph — no edge position, no cable, nothing to drag or wire.

  • Honest about what it is: nothing on the board can be connected to it, because nothing produces it.
  • Costs the least ink of the three and cannot be confused with any port.
  • Says "this block is not pure" without saying which line, which call, or what it read — the least informative of the three by construction.

4 · Decision surface

Done and proved

  • The default-position collision (§0) verified by reading reconcileEffectPorts and EFFECT_EDGE_T_DEFAULT directly, not assumed.
  • 10 orthogonal variants drawn in the app's own idiom; 5 shortlisted and stress-tested across 9 hostile boards (45 panels).
  • Every effect kind Zach might reach for next — receiver, global, I/O, hidden state, raise, resource, async, logging — placed against the shipped model with a specific reason, not a hand-wave.

Left

  • Not built: any of the ten variants — this page is evidence and drawings, not an implementation.
  • Not started: spreading new effect ports apart automatically instead of stacking them at 0.5 (the §0 fix every variant here otherwise has to work around by hand).
  • Not modelled: the receiver row's `mutates` toggle in the inspector UI — the model supports it per the code read in the kind table; whether the UI exposes it is unverified.

Needs you

  • Which variant, or which combination. No default offered — that is the one call this page deliberately does not make.
  • Hidden state's edge. Top-bidirectional, a second left lane, or a non-port glyph — three real answers with different costs, no winner argued for.
  • Logging/telemetry. Drawn at all, suppressed to a tiny mark, or left off entirely — the live question the prompt raised, still open.

Deliberately not done

  • No app or model code touched — every board here is SVG in the idiom, per the hard constraint on this pass.
  • No golden or analyzer exercises two simultaneous mutated arguments today, so every board on this page is anticipatory hardening, not a regression fix.
  • No score, ranking, or "strongest variant" table — flagged verbally where warranted, never as a number.
