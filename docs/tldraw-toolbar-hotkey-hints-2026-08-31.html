Recommended first

Reveal tldraw’s existing slot numbers

Add a CSS counter to the stock toolbar buttons. This preserves <Tldraw>, its overflow behavior, tooltips, accessibility labels, and keyboard handler.

  • No components override
  • One small CSS rule set
  • Risk: selectors follow tldraw’s internal class names, so retain the exact 5.3.2 pin and add one DOM regression test before upgrading
.tlui-main-toolbar__tools > .tlui-row {
  counter-reset: tool-slot;
}

.tlui-main-toolbar__tools > .tlui-row >
.tlui-button__tool[data-toolbar-visible='true'] {
  counter-increment: tool-slot;
}

.tlui-main-toolbar__tools > .tlui-row >
.tlui-button__tool[data-toolbar-visible='true']::before {
  content: counter(tool-slot);
  position: absolute;
  right: 5px;
  bottom: 3px;
  font-size: 8px;
  font-weight: 700;
  opacity: .58;
}
Only for exact fidelity

Own the toolbar and its key map

Use tldraw’s supported TLComponents.Toolbar seam and render a small SystemSketch toolbar. This is needed if Hand must sit before Select yet remain unnumbered, or if ten fixed tools must always show 1…0.

  • One owned TSX component + CSS
  • Still uses tldraw’s tools and editor
  • More maintenance: responsive overflow, tool lock, drag-from-toolbar, tooltips, focus states, and keyboard behavior become SystemSketch responsibilities

The previous pyblocks prototype already contains a working owned-toolbar donor with visible badges; reuse that pattern rather than inventing a third one.
