1 · Rebinding and mutation are two different pictures

You put it exactly right: if we were reassigning the variables then it would look like that, but we are not. The two cases differ in one fact, and everything else follows from it.

Rebinding — poses = extend(poses, pose) — produces a value with a name, so it leaves by an output port, the link to the input is broken, and downstream is an ordinary data cable. That is the board I drew, and for that case it is right. Mutation — poses.append(pose) — produces a value with no name and no return channel. There is no output port to break the link to, because there is no output port. The list reaches len() only because the object it already had was changed.

So the heavy cable in your drawing is not a redundant second rendering of a data edge. It is the edge. Delete it and the board is disconnected.

This part stands. A read takes the latest writer at or before it, so statement order decides and the canvas never has to. Run on your exact program:

4 · Nesting: the same rule at each level, and it terminates

Also unchanged, and it is the answer to "how do you keep propagating outwards". A function mutates a parameter when it writes it in place or hands it to a callee that mutates the parameter in that position. Iterate over the call graph; the sets only grow and the parameter list is finite, so it converges. It stops where the object was created: a local is on nobody's interface, so there is no port for the arc to land on and nothing to carry outward.

Always all the way through, collapsed or not. The badge is read off the signature, and a signature is exactly what a collapsed block shows. A collapsed run() that hid the hook would be lying about its own interface — and now more than before, because with no return port the effect edge is the only thing connecting it to what comes next.

5 · Two mutations: still no second lane

Your stacking rule works, and the reason it feels bad is right: at three writes it is three lanes converging on one port and you cannot eyeball which value leaves. The conclusion survives the correction, though the drawing changes — none of these three calls returns anything, so every edge below is an effect edge.

The stacking only exists because every lane is trying to reach the same port. Let each writer feed the next through its own effect port and the board is a chain again, read left to right, with exactly one write-back at the end — which is the plain answer you already gave for which value leaves run(). You keep what you wanted (trace back along the cable to where it came from) and lose what you did not (N lanes). If you do keep lanes in the lens, ordinal the pills — mut ①, mut ② — rather than telling them apart by geometry.

6 · Effects leave the top, and travel right

Once the effect port turned out to be a real port — one you can grab and wire by hand — the question of which edge stops being decoration. Your rule: the whiteboard may route a cable anywhere, but the linter should prefer an effect that leaves the top and goes right. It is the right rule, and the reason is that the other three edges are already spoken for.

Left — values in.
Right — named values out, by an output port. A mutation has no name to leave by, which is the whole of §1.
Bottom — the loop lane, from the L1 back-cable default.
Top — the only edge left, and now the one that matters most: a value that leaves it and travels right keeps the board readable in one direction.

What changed on this page because of that. Earlier boards here drew the write-back looping back left, into the input port that named the object. That is gone. An input port that was also a source was always the odd part — now the input port keeps the hook (the signature saying I will change this) and the new value leaves by the top, level by level, stepping up and to the right. The nesting board above is the same rule three times: outer.poses → run.poses → add_pose.poses, each inner effect port feeding the next one out.

The port has no slot — it is placed by the cable. You are right that it should not sit at a fixed spot on the edge: the effect port is derived twice over, its existence from the signature and its position from wherever the cable you drew crosses the boundary. Drag the cable and the port follows; route it out of a different edge and the port moves to that edge. That is looser than the Branch region's control ports, which are derived but slotted, and it is the right kind of loose for a whiteboard — the linter has an opinion about which crossing it prefers, and no power to stop you.

The algorithm is written, and it is not about mutations. You asked for it to be general purpose, so it takes a rectangle and a polyline and answers where they meet — nothing about effects, ports or Python. src/blocks/elbow/boundaryCrossing.ts (5 exported functions, 13 test cases, all green) lives with the rest of the pure routing geometry: no tldraw, no React, no DOM, no runtime deps. It clips each segment against the box (Liang–Barsky, so a diagonal or a flattened curve works as well as an orthogonal route) and returns, for every crossing, which side, exactly where, which segment and how far along it, and the arc length from the start — that last one so a caller can place a thing by distance the way a delayed cable's z⁻¹ pill already is. firstExitPerBox does a nested stack in one pass, which is the block-inside-region-inside-frame case. The same call serves a group boundary port, a Branch-region tunnel, a collapsed-group crossing badge, or a clip marker; a mutation's effect port is just the first caller. Two conventions worth knowing: a point exactly on the boundary counts as on, so a stub starting on a block's top edge exits at its own first point; and a cable drawn to land on an edge exits there rather than being ignored, because that is the authored case. prefersSide reports the linter's opinion and never rewrites a route.

And chaining is the case that makes it earn its keep. In-place APIs exist precisely so a large object does not have to be copied, so a run of mutators over one buffer is idiomatic Python, not a smell. Drawn as a left-to-right chain of effect ports it is concise and it reads in the direction the code was written; drawn as N write-backs converging on one place it is neither. The two boards in §5 are that comparison.

Two crossings, not one, and only the first is measured below: an effect leaves the block by its top edge (the rule), and then crosses the enclosing frame somewhere (the derived port's position). The panels above vary the second; the tally counts the first.

The lint, run on this page's own boards. Every effect cable drawn here records the edge it leaves by. 29 of 29 leave the top — no offenders. The rule as the linter would state it: an effect edge leaves the block's top edge, then travels right. It is a preference, not an error: a board that routes one by hand is not wrong, it is a board.

7 · Your three questions about the cable

Answers, corrected. Colour: I said make it an ordinary grey data cable "because it is one". It is not one, so that answer goes. An effect edge carries a value that has no return channel, and a board that draws it identically to a return has thrown away the distinction you just made. Keep it heavy and distinct — your instinct — with the mut pill naming it. What I would still avoid is pure black: the region divider and control cables already own that ink. A dark warm ink, or the existing near-black at a lighter weight than a control line, keeps the two apart. Over the top vs offset: unchanged, and now it barely arises — the effect edge starts at the top of the mutating block, not at the port, so it does not naturally lie on top of the stale wire at all. Where they do converge at a consumer, take L2: the dead wire at 18%, the live one at full weight. Transparency: yes, at the 18% you already settled for a non-live cable, so a board has one fade.
Future — the fade should happen on its own, and it needs no new rule. Your note, recorded here so it is not lost: when you add a mutating call and do not delete the cables that were already there, those cables should grey themselves out rather than sit on the board as lies. That is the many-to-one active-path rule with one word changed. There, several cables land on one port and the live one is chosen by which arm is running; here, several cables carry one name and the live one is chosen by which version reaches this read. Same φ, same 18% token, same lint shape — a port with more than one producer is legal only when something makes them exclusive, and a version boundary is exactly that something. So the behaviour is: drop a mutating call onto a wired board, and every read downstream of it re-binds to the new version while the old cables fade. Nothing is deleted, nothing is moved, and undo puts it back. Not built — this is a note for later, and it is the natural next step after the analyzer emits effect ports at all.

8 · The refactor argument gets better, not worse

I claimed that swapping in poses = [*poses, pose] moves no cables. That was true only under the fiction. What actually happens is more useful: the refactor converts effect edges into data edges. The probe reports 0 write-backs afterwards — the effect port disappears, a real output port appears in its place, the hook comes off the input, and run()'s signature stops carrying the effect. The consumers stay bound to the same versions; only the channel they arrive by changes.

def run(raw: bytes, gain: float, poses: list[Pose]) -> int:
    frame = decode(raw)
    pose = estimate(frame, gain)
    random_func_before(poses)
    poses = [*poses, pose]
    random_func(poses)
    count = len(poses)
    return count

Which makes the two boards in §1 the before and after of one action: right-click the effect port → make this pure, with the diff shown before you accept. The left-hand board is what you get. That is still the feature underneath all of this, and the correction sharpens it rather than weakening it.

One free cue worth taking. -> None is Python's own way of saying "this exists for its effect" — the same thing Rust says with () and Haskell with IO (). A block with inputs and no output port at all is therefore already legible as a mutator or a sink, before any badge or pill is drawn. It costs no ink, and it falls out of drawing the signature honestly.
