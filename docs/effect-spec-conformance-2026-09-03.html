A mutation is drawn, not hidden. Refusing to render an impure call was the first instinct and the worst option.

An argument marked mutates grows a hook on its input and an effect port on the block's top edge. Driven end to end in the browser: 19 checks in tests/effect_ports_smoke.mjs.

There is no return channel, so the effect is the only way out — not a second drawing of a data edge.

A mutating call is given no right-hand port; the effect port is the only source. effectCable.ts derives the cable's look from that port, so the fact lives in one place. The pop family — which returns a value and mutates — keeps both, asserted in effectPorts.test.ts.

Crossings are allowed, not prevented.

met

Left values in, right named values out, bottom the loop lane, top effects.

Effect outputs are pulled out of the right-hand lane before the body is planned, so they take no row slot and nothing below them moves — asserted by comparing a marked block against an unmarked one.

met

Out of the top first, then turn.

The router used to hardcode side: 'right' for every terminal. It is now told the port's real edge. The journey parses the rendered path and requires the first run to be vertical over ≥8px (EP-9b).

partial

the positioning of the mutating port ... perhaps it can just appear wherever we end up drawing the mutating arrow? you see where it intersects the boundary and drag the port there

The port's position is derived from the drawing, not from a slot.

The rule and its geometry are written and tested — effectPortFollow (9 cases) on top of boundaryCrossing (13 cases) — and it is installed as an editor side effect. But it cannot fire. See the finding below: this app refuses a cable between two scopes, so no cable ever crosses a frame edge to be measured. Position today comes from the spread default and from dragging.

met

The crossing algorithm must not be about mutations.

src/blocks/elbow/boundaryCrossing.ts takes a rectangle and a polyline and reports side, point, segment, t and arc length; firstExitPerBox does a nested stack in one pass. It sits with the pure routing geometry, imports nothing from the app, and names a group boundary port, a region tunnel entry and a clip marker as equal callers.

partial

What happens if you have like multiple ports that are being mutated. how can you tell them apart?

Two mutated arguments must be distinguishable.

The collision is fixed — ports used to be born at 0.5 every time, so two landed on the same point. They now spread as (i+1)/(N+1) in argument order, and the tether says which hook each belongs to. The ten-variant study of stronger marks (label, pill, colour, ordinal) is drawn but nothing from it is chosen or built.

2 · The one finding that changed the picture

This app does not let a cable cross a frame, so there is no crossing to measure. connectionRules.ts carries an explicit refusal, 'no-shared-scope': the two Blocks must share a scope, and the interior of an expanded Block is a scope. A boundary is crossed by binding to the frame's own port — inner face on one side, outer face on the other — which is exactly what golden 11's target board does. So the follow rule, written to measure a geometric crossing, is installed but inert. The journey that was meant to prove it gets four checks in and then legitimately cannot draw the cable, which is how the finding surfaced. An earlier version of that test passed this step, because it dropped the cable on empty canvas, made nothing, and my assertion was satisfied by the frame resizing — the tightened version measures where the painted path actually crosses and the false pass disappeared. The fix is small and not a rethink: drive edgeT from the inner-face binding's endpoint rather than from a crossing. Still calculated from the arrow you draw, measured at the port instead of the frame edge.

A port is on the top edge because its dot is painted there; a tether is right-angled because its rendered d attribute parses that way; it is render-only because the computed style says so.

4 · What I would do next, in order

  1. Re-point the follow rule at the inner-face binding, so the outer port is positioned by the cable again. Removes the one inert piece.
  2. Pick a mark for multiple mutations from the ten-variant study, so three mutated arguments are distinguishable by more than order and a tether.
  3. The auto-fade, which needs no new mechanism.
  4. The analyzer: emit effect ports from real Python instead of a hand toggle.
