Five loop grammars, from LabVIEW's answer outward

The previous ten were rejected in full. This pass throws them away and starts from the question underneath: who owns the unpacking, and who owns the delay? Every variant here answers that differently, and not one of them adds a Block, a gate, a state pill or any other node. Nothing in src/ was changed.

The model, before any picture

A for statement puts exactly four new facts into a dataflow graph. Naming them first is what stops a grammar from being decoration.

#FactWhat it forces the drawing to say
F1A scope with a repeat count Some sub-graph runs N times while everything around it runs once.
F2A rate change on the way in Outside, others is one value of type Poses. Inside, other is one Pose per turn. Something distributes one collection over time.
F3A rate change on the way out Per-turn becomes once again — either the last turn's value survives, or every turn's value is collected.
F4A one-turn delay on anything read and written pose = merge(pose, other). Turn i's write is turn i+1's read. Turn 0 reads the seed from outside. This is the only genuinely temporal fact, and it is exactly z⁻¹.

Two ownership questions fall straight out of F2 and F4, and prior art has already answered them in every possible way:

QuestionAnswer AAnswer BAnswer C
Who owns the unpacking? The wall. The cable is ordinary on both sides; the boundary transforms it. LabVIEW auto-indexing tunnel, Houdini Block Begin. The cable. The wire itself carries cardinality; the boundary is dumb. Grasshopper trees, LabVIEW's thicker array wires. The consuming port. The target name creates the element. Python itself; n8n's run-once-per-item.
Who owns the delay? The wall. A matched pair of terminals, and no cable at all. LabVIEW shift register. The cable. A dotted line with a z⁻¹ mark. Already shipping in SystemSketch. A node. Simulink's 1/z block — ruled out here, because it adds a block.

Cross the two surviving columns and you get four honest variants, plus one degenerate corner where the scope is not drawn at all. That is the set below — it is a spanning set, not a list of ideas.

The prior art Zach pointed at

The two things LabVIEW gets right, and which the rejected set never used, are both properties of the border rather than objects beside it: the auto-indexing tunnel (a collection outside, one element inside) and the shift register (a matched pair of terminals that hands a value to the next iteration). Neither is a node.

The five

All five draw the same loop — the one from the note. The blocks, the ports and the outer values are identical in every picture, so a difference below is a difference in the grammar and never a difference in the drawing.

def run(raw: bytes, gain: float, others: Poses) -> bytes:
    frame = decode(raw)
    pose = estimate(frame, gain)
    for other in others:
        pose = merge(pose, other)
    payload = encode(pose)
    return payload

V1  Wall Tunnels

The boundary owns both the unpacking and the delay. Nothing crosses the body.

Owns the unpackingthe wall
Owns the delaythe wall
Prior artLabVIEW auto-indexing tunnels and shift registers; Houdini's Block Begin/End; Blender's Repeat Zone.

A cable does not simply pass through the loop's border — it goes through a mouth on it, and the mouth says what the crossing does. [ ] means the collection outside arrives as one element inside. A plain filled square means the value is the same every turn.

The carry is a matched pair of mouths — ▼ on the left wall, ▲ on the right, at the same height, wearing the same name. The right one swallows the body's value at the end of a turn; the left one hands it back at the start of the next. No cable is drawn between them, which is why the interior stays completely clean, and why the loop's final value leaves through that same right mouth once the loop is over.

The iteration counter is a terminal on the bottom wall — Zach's "iterator port that emits the iterator value", exactly where LabVIEW puts i.

What it costs. The carry has no visible path. Two marks have to be paired up by name and alignment, which is the one thing Zach's own note argues against — he wrote that he prefers the z⁻¹ line that goes straight into the port.

V2  Cardinality Cable

The cable carries the rate. The wall is unmarked; a collection is a doubled rail that thins where it enters.

Owns the unpackingthe cable
Owns the delaythe cable
Prior artLabVIEW draws array wires thicker than scalar wires; Grasshopper's data trees; Blender field wires; ER-diagram crow's-foot cardinality.

A cable carrying a collection is drawn as two rails. Where it enters the loop it becomes a single rail. That transition is the unpacking — no glyph, no mouth, nothing to learn beyond "thick means many". On the way out, single→double is a collection being built; single→single is a last value.

The carry is an ordinary SystemSketch cable with temporal: delayed — the dotted paint and the z⁻¹ pill that already ship — routed beneath the body so it reads as a return rail rather than a competing arrow.

Nothing else is added. This is the only variant that needs no new object at all: one line weight, and machinery the app already has.

What it costs. Nothing here can express zip, tuple unpacking, or where the iteration counter comes from — with an unmarked boundary there is no object to ask. A second carried value is a second rail across the floor.

V3  Binding Ports

Python's own ownership: the target name makes the element, so the consuming port carries the mark.

Owns the unpackingthe consuming port
Owns the delaythe port pair
Prior artPython's own semantics (`for X in Y` binds X); n8n's run-once-per-item; Verilog's implicit `always` sensitivity.

Nothing is added to the wall and nothing is added to a cable. The body block's own port row says what it is: [·] other means this port takes one element per turn from whatever collection feeds it, and ↺ pose pairs an input with the output that rewrites it.

This is the least ink of all five. The diagram of a loop body is the diagram of a straight-line body plus two small badges.

What it costs. The recurrence has no path at all — the reader must pair two badges by name. That is a bigger version of V1's problem and it fails outright once a carried value spans two blocks. Scored honestly, it is last.

V4  Header Contract

Every name the `for` binds is one row on the region header, and that row owns the wall ports for it.

Owns the unpackingthe wall, named on a header row
Owns the delaythe row itself — the return line runs along it
Prior artLabVIEW's tunnel, given a name; Houdini's Block Begin parameters; MLIR's `scf.for` iter_args; Zach's own Branch-authoring lean toward inspector lists with control ports derived from the arm code.

The header is not a title and not decorative source. It is a list of the loop's bindings, one per line, and each line owns a real port on the wall. for other in others gets a port whose outer face is the collection and whose inner face is the element — which is exactly SystemSketch's shipped inner-face model: one dot on screen, two identities.

A carry row is drawn as one horizontal line running the width of the header: solid where it leaves the body, dotted with the z⁻¹ pill through the middle, solid again into the port. Zach's preferred solid-before / dotted-after treatment, and the recurrence never enters the body area at all.

Because the row is a sentence, it can carry things no mark can: for i, (name, box) in enumerate(zip(names, boxes)) is one row handing out three taps. break when … and else … are simply two more rows.

What it costs. The header grows a small layout language, and a loop with four bindings has a four-line header. An invariant costs nothing — it binds no name, so it gets no row and crosses unmarked.

V5  Bare Cycle

No scope is drawn at all. A dataflow graph that contains a cycle already IS a loop.

Owns the unpackingthe cable
Owns the delaythe cable
Prior artSynchronous dataflow (Lustre, Signal); Simulink's unit-delay feedback; LabVIEW's Feedback Node, which is the shift register with the loop border taken away.

One solid cable from others to merge.other with a cardinality tick near its head. One temporal: delayed cable from the output back to the input, closing the cycle. That is the entire notation.

The tint is derived — the app finds the strongly-connected component and washes it — so the loop's extent is a consequence of the wiring rather than something the author drew. The live iteration counter rides on that tint, which answers Zach's "show the iteration number" idea for while-loops too.

What it costs. With no scope object there is nowhere to put `break`, `for…else`, or an empty iterable's default, and two loops sharing a block collapse into one blob. It is the right answer for simple loops and the wrong one for the hard suite — which is precisely why it is in the set rather than the finalists.

Criteria, then scores

The criteria and their weights were written down before any variant was scored, and they are tilted the way Zach's own note is: the two things he says the drawing must make obvious are worth 18% each, and “adds no node” is a hard gate rather than a tie-breaker.

The three taken forward

They are not three flavours of one idea — they put the loop's meaning in three genuinely different places, which is what makes the fifteen examples below worth comparing: on the header, on the cable, and on the wall.

V488.0

Header Contract

Every name the `for` binds is one row on the region header, and that row owns the wall ports for it.

V282.3

Cardinality Cable

The cable carries the rate. The wall is unmarked; a collection is a doubled rail that thins where it enters.

V179.9

Wall Tunnels

The boundary owns both the unpacking and the delay. Nothing crosses the body.

Why V4 leads, in one sentence. Every other variant invents a mark and then has to teach it; V4 writes the binding the way Python already writes it and hangs the ports off that sentence, so the only thing a reader has to learn is that the header line is where the loop's names live — and the header row is also the one place that can hold zip, a tuple unpack, break, else, and what happens when the collection is empty.

The tension I want your call on. LabVIEW's shift register is the calmest thing in this entire document — the recurrence costs zero cable. But it works by making the value teleport between two paired marks, and your note says the opposite: “I prefer the z⁻¹ line that goes straight into the port.” V4 is my attempt to have both — LabVIEW's tunnel for the unpacking, your z⁻¹ line for the delay, drawn along the header row so it still never crosses the body. If you would rather have the pure LabVIEW answer, that is V1, and it is a defensible pick.

Fifteen stress examples

Five loops, easy to hard, each chosen for a specific way a loop grammar can break — not for variety. Every one is drawn three times, with the body held identical.

L1 · map · invariant · packed result

thumbs = []
for f in frames:
    thumbs.append(shrink(f, size))

What it is here to break:

  • no carried state — the delay machinery must fall completely silent
  • `size` is loop-invariant and must NOT be unpacked
  • the result leaving is a collection, not a last value
V4 Header Contract holds

Two rows, and the invariant costs nothing — V4 only spends a row on a name the `for` actually binds. Reads aloud correctly.

V2 Cardinality Cable holds

The strongest showing. The doubled rail thins at the wall and thickens on the way out; `size` crosses with no mark at all; and because nothing is carried there is simply no rail. Silence is free.

V1 Wall Tunnels holds

Four distinct glyphs already: index in, plain in, index out. Correct, but a two-line loop has spent most of the vocabulary.

L2 · reduce + collect from one body

pose = estimate(frame, gain)
trail = []
for other in others:
    pose = merge(pose, other)
    trail.append(score(pose))

What it is here to break:

  • a carry and a packed result leave the same turn
  • the value `score` reads is THIS turn's, not last turn's
  • the carry's final value and the collection exit side by side
V4 Header Contract holds

Three rows, three sentences. `carry` and `collect` are visibly different verbs, which is exactly the distinction the reader needs.

V2 Cardinality Cable strained

The return rail now shares the region floor with the packed exit, and the reader has to check whether `score` reads the pre- or post-merge value. It reads correctly, but only after tracing.

V1 Wall Tunnels holds

The ▼/▲ pair and the indexed exit sit on different walls and do not compete. Nothing crosses the body — still the calmest interior.

L3 · enumerate · zip · tuple unpack

best = None
for i, (name, box) in enumerate(zip(names, boxes)):
    score = rate(box, gain)
    best = pick(best, score, name, i)

What it is here to break:

  • four names bound by ONE `for`, from two collections plus a counter
  • `score` is a loop-local: written and read in the same turn, never carried
  • `gain` is invariant and `i` has no outer source at all
V4 Header Contract holds

The decisive case. One row carries the whole Python binding and hands out three taps, so zip, the tuple unpack and the counter are one statement instead of five unrelated marks.

V2 Cardinality Cable fails

Nothing on a cable can express `zip`, and the counter `i` has no source: with no marked boundary there is no object to ask for it. Drawn here as an unexplained chip, which is the honest depiction.

V1 Wall Tunnels strained

Two index mouths, one plain mouth, one carry pair and the counter terminal — five marks on one wall, and NOTHING says the two index mouths were zipped rather than iterated independently.

L4 · continue · conditional collect · empty

total = 0.0
kept = []
for d in detections:
    if d.score < thresh:
        continue
    total = total + weight(d)
    kept.append(d)

What it is here to break:

  • a skipped turn writes NOTHING — the carry must survive untouched
  • the collection gets an element on some turns and not others
  • `detections == []` must leave total at 0.0 and kept empty
V4 Header Contract holds

The two notes are the answer: `unchanged on a skipped turn` and `appended only when the guard passes` are properties of the BINDING, and the binding is the thing V4 draws. Nothing else has a place to put them.

V2 Cardinality Cable fails

The rail is drawn as if it always carries a value. On a skipped turn the same rail must silently mean "unchanged", and no line weight or dash can say that. The empty case is invisible.

V1 Wall Tunnels strained

LabVIEW's own answer is a conditional tunnel with an "if empty" default, and it works — but the default value for an empty run lives in a property dialog, not on the canvas. The picture cannot tell you what `kept` is when nothing matched.

L5 · nested · break · for…else

misses = 0
for track in tracks:
    for det in track.dets:
        if match(det, query):
            hit = det
            break
    else:
        misses = misses + 1

What it is here to break:

  • an inner iterable that is an ATTRIBUTE of the outer element
  • `query` is invariant across BOTH boundaries
  • `break` leaves the inner scope early; `for … else` runs only when it did not
  • `hit` is written inside the inner loop and read outside both
V4 Header Contract holds

Six rows, six sentences, and `break` and `else` are simply two more of them. The inner header names `track.dets` — the outer element's own attribute — which no mark on a wall or a cable can say. `query` crosses both scopes unmarked because it binds nothing.

V2 Cardinality Cable fails

Two rate changes on one path (`Tracks → Track → Dets → Det`) are legible, and an invariant crossing two scopes costs nothing — genuinely V2's best trait. But `break` produces a bool with nowhere to land and `else` has no object to attach to. Both are drawn in warning colour because that is the truth.

V1 Wall Tunnels strained

Nesting is LabVIEW's home ground and it holds: two walls, two sets of mouths, a real conditional terminal for `break`. The costs are that `query` pays a mark at every wall it crosses for changing nothing, and that `for … else` has no terminal at all — the band around bump() is drawn here, not modelled.

Where this leaves the design

Two findings are worth more than the ranking.

The type already carries the unpacking. A boundary port whose outer face reads Poses and whose inner face reads Pose has said the whole thing without a single new glyph — and SystemSketch already models a port with two faces (PortFace = 'outer' | 'inner' in src/blocks/connections/connectionModel.ts, present in this tree: True). That is the cheapest true statement available and every variant here should probably use it.

An invariant should cost nothing. gain and thresh and query bind no name and change no rate. V1 makes each of them pay a mark at every wall they cross — twice over, in the nested case. V2 and V4 charge them nothing. That is a small thing that shows up on every real diagram.

Held out deliberately. No product feature was implemented, no file under src/ was touched, and nothing here is wired to the toolbar. The temporal StyleProp used for every dotted cable is the one that already ships ('data', 'async', 'delayed', with the z⁻¹ pill), so a real implementation of V2 or V4 would start by reusing it rather than adding paint. `while` loops, `zip` of unequal lengths, generators and `itertools` are all out of scope for this pass.

A product finding that fell out of building the boards. SystemSketch refuses a cable from a Block to itself, so the motivating loop's own recurrence — pose = merge(pose, other), a single Block — cannot be drawn as a real cable today. The five-variant board therefore uses a two-step body (merge then smooth) so that every carry is a genuine temporal: delayed record; the stress board says on each card where a carry had to be drawn rather than wired. Whatever grammar wins, a one-Block accumulator is the most ordinary loop there is, and the editor cannot express its recurrence.
