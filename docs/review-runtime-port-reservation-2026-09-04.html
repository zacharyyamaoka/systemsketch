SystemSketch · review runtime repair

A durable review URL stays bound to its own board.

The screenshot was not a board-access policy problem. A later retained review reused an earlier review’s localhost port; its server correctly rejected the other review’s board as outside its own pinned checkout.

Before

One port, two records

A stopped review still owned a published URL, but allocation checked only currently bound sockets. A later review could reuse the pair.

old board URL → :4606
:4606 now serves another pinned worktree
foreign board path → safe root rejection
After

Registry reservation

Every retained review reserves both its public and API ports until it is explicitly removed. Publishing skips those pairs even when their processes are down.

old review → reserves :4606/:4607
new review → chooses an unused pair
old URL → its own board when restarted

The safe boundary is unchanged

Direct board URLs remain confined to the review’s immutable checkout. This fixes the routing error without granting one review server write access to every sibling review board.
