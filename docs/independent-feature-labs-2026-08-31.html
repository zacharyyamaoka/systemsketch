Architecture decision · 2026-08-31

One product entry.
Many independent labs.

A feature should be developed against stock tldraw plus its own capability—not against whichever SystemSketch chrome, workspace, or other feature happens to be changing today.

No separate compiled app per feature.

Use development-only composition profiles such as /?lab=block. Keep / as the sole production composition.

Integrated product: the profile composes every accepted capability. Integration is a deliberate gate, not where a feature is born.

The three rules

These are the real independence mechanism.

1

Feature owns a closed directory

Model, rendering, commands, tests, and lab adapter live together. Another feature cannot reach into its internals.

2

Labs depend downward only

A lab imports stock tldraw and one feature. It does not import production chrome, workspace, or another volatile feature.

3

One writer owns integration

Parallel lanes never all edit App.tsx. They hand back capability exports; one integration pass changes the product profile.

When is a truly separate entry point justified?Only when a feature requires an incompatible runtime or is independently deployable. Visual experiments, custom shapes, inspectors, bindings, and interaction work do not meet that bar.
Evidence boundary: based on the current SystemSketch composition in src/App.tsx, where all accepted capabilities presently converge. This report proposes the next isolation seam; it does not claim that the profile layer has been implemented.
