Draft branches without pages

A named, editable alternative of one SystemSketch document is useful for prototyping. The earlier PyBlocks study already selected the relevant IcePanel model: an isolated Draft from a known Current state, plus immutable Versions. It also explains why a tldraw page is the wrong storage mechanism.

Decision carried forward

Draft + Version is the correct backbone for personal “try several things without disturbing the real board” work. The report recommends a conservative first promotion rule: a draft can replace Current only when Current still equals the digest the draft started from. A changed Current is a visible stop, not a hidden last-writer-wins merge.

What a document draft means

Proposed first workflow, not present product UI. Each state is the same single canvas at a different document revision; no page records stand in for a branch.

Why not pages

The prior study tested it

Pages as Board States scored 72.2, last of the 5 alternatives. It keeps the useful idea—fast visual switching—but loses a real base/merge relationship because duplication creates independent record identities.

It also overloads “page”: a spatial section, a navigation target, and a proposal would become one ambiguous thing.

The active product makes the boundary explicit

maxPages: 1 is measured from src/App.tsx. Legacy-page migration is present; imported pages become named stock Frames on one root canvas.

Drafts should therefore switch the document snapshot beneath the same canvas, while Frames and Depth Stack continue to express structure and navigation.

Review Patch remains the strongest later splice: it can provide per-change accept/reject inside a draft. It should not replace a whole-board draft for an hours-long exploratory redesign. Git Native remains valuable for code-derived PyBlocks projections, but asks a standalone whiteboard user to own repository state.

What is already real, and what is not

Available building blocks

  • Complete board serialization and atomic local-file writes.
  • Content-digest fence: present in the current workspace client.
  • Clean external reload versus a visible Current-versus-disk conflict.
  • One-canvas migration, Frames, and ephemeral structural Depth navigation.

Not shipped

  • Draft metadata, heads, a draft picker, or an amber draft-mode bar.
  • Immutable document-version storage and non-destructive restore.
  • Record-aware comparison, three-way merge, or visual conflict resolution.
  • Review Patch ghosts, cross-document drafts, collaboration, or Git checkout.

Safety rules inherited from the selected model

  • Current remains an ordinary .systemsketch file. The board must stay portable, agent-readable, and openable even when optional history metadata is absent.
  • No blind stale promotion. Every draft, patch, restore, or branch must be checked against the digest/revision it started from.
  • Versions are immutable. A recovery point is trustworthy only when viewing or restoring it cannot rewrite it.
  • Non-current mode is continuously visible. A user must never accidentally believe a draft, suggestion, or historical snapshot is Current.

    • Recommended delivery order

    01
    Immutable version foundation. Store named, read-only serialized snapshots without changing the ordinary Current-file format.
    02
    Named local drafts. Capture base digest plus snapshot, autosave only the draft head, and make Current/Draft mode continuously visible.
    03
    Conservative promotion. Allow only unchanged-base promotion; save an immutable version before advancing Current.
    04
    Compare before merge. Add record-aware revision diff, then explicit conflict handling. Do not promise a three-way merge before it exists.
    05
    Selective review later. Add revision-linked Review Patches only when per-change collaboration becomes the actual bottleneck.
