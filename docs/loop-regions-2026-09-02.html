How node editors draw “do this again.”

Five real node-editor screenshots first, then the same Python loop drawn five ways in SystemSketch. The visual question is narrow: where does the loop live, where does the current item come from, how does a value reach the next iteration, and what leaves after the loop runs zero or more times?

1 · Comparison contract

The criteria and gates below were frozen before the five alternatives were scored. The common fixture is 10_loop_carried_state; every candidate must explain the same seed, one body write, one next-iteration hand-off, and one after-loop read.

Weighted objective · fixed before the boards

  1. c1 · Dataflow evident, iteration included (25%) — A reader follows one pass left to right and sees where the value comes back, and what leaves after the last pass.
    1 / 3 / 5 anchors1: the cycle is hidden · 3: iteration is visible but one transition is implicit · 5: seed, next iteration, and exit trace directly
  2. c2 · Says what the code says (20%) — One block per call; no node the text lacks; the seed, the write-back and the read-after are the code's three uses of the name.
    1 / 3 / 5 anchors1: several invented nodes · 3: one explicit helper convention · 5: the marks correspond directly to calls and value uses
  3. c3 · Scales (20%) — Several carried names, a nested loop, break/continue, zero iterations, a for item and an iterable.
    1 / 3 / 5 anchors1: one carried value already crowds the board · 3: a few values work with lane pressure · 5: many values and nesting stay compact
  4. c4 · Derivable (15%) — Every mark from the two-pass table; nothing authored.
    1 / 3 / 5 anchors1: requires authoring · 3: partly inferred · 5: emitted mechanically from the loop table
  5. c5 · Reuses the branch grammar (10%) — Region, band dots, ordinary fan-in, fold and active; no new vocabulary.
    1 / 3 / 5 anchors1: replaces the region grammar · 3: extends it with one new convention · 5: only existing region, dot, receiver, and cable marks
  6. c6 · Buildable on stock tldraw (10%) — Frame, children, cables, bindings; a cable may already close a cycle.
    1 / 3 / 5 anchors1: engine work · 3: custom rendering layer · 5: existing stock shapes and bindings

Hard gates · pass / fail, never averaged

2 · Five editors, visually

These are vendor-documentation captures, not redraws. Orange numbered markers isolate the mechanics that matter; the surrounding UI remains visible so each convention can be judged in its native visual language.

Region + shift-register pair

LabVIEW

123

The loop is the rectangular region. Each left/right terminal pair is one carried value: seed enters at left, the body writes right, and right becomes both next iteration and the final outside value.

1N=10 controls how many times the region executes.
2Left terminals deliver the seed first, then the previous iteration's value.
3Right terminals accept this iteration's write and expose the last value outside.

Repeat zone + repeat items

Blender Geometry Nodes

123

The orange zone is the loop. The left Repeat node initializes named items; the right Repeat node writes their next value and is also the zone's final result. The top socket emits the iteration index.

1Iterations sets the count; Iteration emits the current index.
2Geometry enters the zone as the initial carried item.
3Repeat Output supplies the next iteration and the result after the last.

Block Begin / End + reference

Houdini SOPs

123

The orange outline is the loop body. Block Begin uses the input on iteration one, then fetches Block End's previous result by reference. The graph stays visually acyclic; the named relationship carries the cycle.

1Fetch Feedback returns the input on pass one and the end result thereafter.
2Every node inside the orange block runs once per iteration.
3Block End pairs with Begin and emits the final geometry.

Iterator subsystem + Memory

Simulink

123

The subsystem supplies a For Iterator block. State is a separate Memory/Delay block: the sum writes it, and on the next iteration Memory feeds that stored result back into the sum. The delayed initial condition defines iteration zero.

1The For Iterator consumes N and emits the current 1:N index.
2The body combines this index with the carried running total.
3Memory makes the return edge one iteration late and supplies the initial value.

Control-flow macro

Unreal Blueprints

1234

ForLoop is a control node, not a data region. It emits Loop Body once per index and Completed once at the end. Any value carried between passes lives in an explicit Blueprint variable, outside the loop node's visual grammar.

3 · Five SystemSketch directions · unranked

Each hero uses the same source and viewport. Click the three semantic steps directly, or press Play to trace the same state machine. Rankings and the AI recommendation deliberately appear only after all five.

L1 · Cycle as a cable

The loop is a region; its only new semantic is an ordinary cable that leaves the last producer and returns to the first consumer.

SeedThe pre-loop estimate enters merge.pose as the seed cable.
Decisions, fit, and trade-off

Your lean, made exact. The write-back is an ordinary cable from the body's last producer back to the body's first consumer, routed to the region's right edge, down into a reserved bottom lane and back — read one pass left to right, then around. The consumer's port is ordinary fan-in, the same as the branch: a seed cable and a back cable into one port. After the loop the reader's one port takes a last-value cable and a zero-iterations cable, because the seed reaches it untouched when the loop never runs.

best when

Any loop a reader wants to trace once; nested loops as nested regions with their own lanes.

loses when

Every carried name is one more cycle and one more zero-iteration cable; three carried names make three lanes.

what exists today

Cables, fan-in (branch grammar), band dots: all drawn already. The lane is a format rule for the routing, not a shape.

L2 · State row on the band

Each carried name becomes a paired state terminal on the region band: current value on the left, next/final value on the right.

SeedThe seed lands on the left state terminal in the band row.
Decisions, fit, and trade-off

LabVIEW's shift register and MLIR's iter_args: each carried name is a pair of dots on a state row under the band — left is this iteration's value, right is the next one's — and after the loop the right dot is what the outside reads. The back-edge is implied by the pair, not drawn.

best when

Many carried names; the reader wants a table of what changes per iteration.

loses when

Adds a mark the code does not have and a convention to learn (the pair means a cycle); the body's first consumer no longer shows where its value comes from.

what exists today

Band dots exist; a second band row and paired dots are new.

L3 · State node

A small named state object inside the region is seeded before the loop, updated by the body, and read afterward.

SeedThe estimate seeds a named state oval inside the loop region.
Decisions, fit, and trade-off

The 10 golden's own target board: a small state node inside the region that is seeded from outside, written back by the body, read by the body and read after the loop. The node is the φ and the unit delay in one oval.

best when

When you want the carried value to have a place to hover, name and probe.

loses when

A node the code lacks, one per carried name; the oval looks like the class-state ovals but means something else.

what exists today

The bootstrap already emits value:pose-2 with seed / after iteration / next iteration cables (measured below).

L4 · Rolled-out ghost lens

A translucent second copy of the body shows the hand-off from iteration k to iteration k+1 as a left-to-right teaching view.

Iteration kThe first copy is the ordinary body for the current iteration.
Decisions, fit, and trade-off

Iteration k solid, iteration k+1 as a 35% ghost, so time flows strictly left to right and the hand-off cable is the carried value. Kept as a lens over L1, never as a structure.

best when

Explaining a loop to someone once, on demand.

loses when

Doubles the body, cannot contain its own nesting, and is the Aug 25 l4 that failed the gutter gate.

what exists today

Nothing; a lens would be a render mode over L1.

L5 · Begin / end pair

Loop Begin and Loop End define the repeated span; the end result feeds the begin node by their paired relationship.

BeginLoop Begin emits the current carried value and the current item.
Decisions, fit, and trade-off

Houdini's Block Begin/End and Anemone's Loop Start/End: no region, two blocks, and the body is whatever sits between them; the end feeds the begin by convention.

best when

Editors without containers.

loses when

Breaks the region grammar; the body's extent is a convention; the back-edge is invisible.

what exists today

Two ordinary Blocks; nothing else.

4 · Why the visual evidence points where it does

“No variables, just flow” is what the rigorous representations do underneath. MLIR carries loop state as region arguments and scf.yield hands the next value around [1]. Dennis's dataflow loop schema is a merge fed by the entry value and the loop-back arc [17]. The shared fact is not a variable; it is two possible producers reaching one consumer.

The zero-iteration path is not optional semantics. After for other in others, pose is merge()'s last result if there was an iteration and estimate()'s seed if there was none. LabVIEW's right shift-register terminal similarly exposes the last stored value [2]. Any visual grammar that hides this case is compact, but incomplete.

Mature tools mark carried state explicitly because an arbitrary backwards wire is ambiguous. LabVIEW uses a terminal pair, Blender uses Repeat items, Houdini references a paired Block End, and Simulink inserts Memory/Delay. A backwards cable becomes unambiguous only when it is inside a region whose contract already says “this runs once per iteration.”

The header produces the item. for other in others consumes others and produces other. LabVIEW's auto-indexing tunnel [4], Blender's Iteration socket [11], and Unreal's Index pin [16] are three native examples of the same distinction.

Routing is formatting. “Go to the end first, then loop back” means right edge → bottom lane → home by default. Tidy can reapply it; the whiteboard can still bend it.

5 · The exact code and the two-pass proof

The analyzer currently collapses the for into one opaque region with 3 inputs and 2 outputs, marks pose in and out as state edges, and emits no edge back. Its diagnostic reads “loop body is collapsed; carried state and iteration count are not expanded in v1”. The authored target disagrees: - **Q4 — is a loop drawn as a cycle.** In `10`, the analyzer emits `region → post-state → consumer` with no edge back into the region. The board asserts the carried value returning, because a backedge is the thing that makes it a loop.

def run(raw: bytes, gain: float, others: Poses) -> bytes:
    frame = decode(raw)
    pose = estimate(frame, gain)
    for other in others:
        pose = merge(pose, other)
    payload = encode(pose)
    return payload

docs/loop_carried_binding.py walks the body twice. A name read before the body writes it resolves to the pre-loop value on pass one and to the body's own write on pass two; that difference is the carried set. After the loop, every written name is a φ of the body's last write and the pre-loop value.

6 · Implementation seam, if L1 is accepted

  1. Lower for and while to one region with one arm. The band carries the iterable or test; a for also emits the item.
  2. Lower the body twice with a copied table. A read-before-write whose two resolutions differ is carried; feed its consumer through seed and back fan-in.
  3. Create an exit φ for every body-written name read afterward. Its reader takes the last and zero cables into one port.
  4. Format the back cable to the right edge and bottom lane. Keep that as an overridable routing preset, not a constraint.
